# 开发文档 · 总体架构设计

> 配套文档：[01-项目计划书](./01-项目计划书.md) · [03-数据库设计](./03-开发文档-数据库设计.md) · [04-API与开发规范](./04-开发文档-API与开发规范.md)

## 1. 架构总览

采用**模块化单体**（Modular Monolith）：一个 Spring Boot 进程，内部按业务域切成强边界 Maven 模块。模块间**只允许通过对方暴露的 API 接口调用，禁止跨模块访问表/DAO**——这是后期可平滑拆微服务的保证，也是借鉴 Odoo"模块只依赖其他模块公开契约"的核心纪律。

```
                          ┌─────────────────────────┐
   Nginx ──► Vue3 SPA ───►│  Spring Boot 单体进程    │
   (静态资源+反向代理)      │                         │
                          │  ┌───────────────────┐  │
                          │  │ api 层 (REST)     │  │
                          │  ├───────────────────┤  │
                          │  │ service 层        │  │
                          │  ├───────────────────┤  │
                          │  │ dal 层 (MyBatis+) │  │
                          │  └───────────────────┘  │
                          └───┬──────┬──────┬───────┘
                              │      │      │
                          MySQL 8  Redis 7  MinIO
```

### 模块依赖规则（纪律性约定，Code Review 红线）

1. 业务模块之间**单向依赖**：如 `sal → stk`（销售出库调用库存过账），禁止反向、禁止循环；
2. 跨模块调用只发生在 `api` 包（每个模块暴露 `XxxApi` 接口 + DTO），例如 `stk` 暴露 `StockMoveApi`；
3. 需要反向通知时用 **Spring 事件**（如库存模块发布 `StockBelowSafetyEvent`，销售模块监听做预警），而不是反向依赖；
4. 模块可停用：`tiangong-server` 的聚合 pom 中注释掉某模块 + `tiangong.modules.enabled` 配置开关，其余模块自动降级（借鉴 Odoo 插件装卸）。

## 4. 核心架构决策（ADR 摘要）

### 4.1 业务单据统一生命周期（借鉴 Odoo draft→done 状态机）

所有业务单据统一实现 `BizOrder` 约定：

```
草稿 draft ──提交──► 待审批 approving ──通过──► 已审核 audited ──执行──► 已完成 done
                        │                         │
                        └─拒绝──► 草稿（驳回）      └─冲销/红字──► 作废 voided
```

- 状态字段：`status`，统一枚举 + 统一流转校验器（`OrderStateChecker`），防跳状态；
- **只有 `audited` 状态的单据才触发库存过账/财务过账**（钩子接口 `OrderAuditListener`）；
- 冲销采用红字单据（不改历史单据），保证审计可追溯（Metasfresh/用友惯例）。

### 4.2 库存双账引擎（借鉴 Odoo）

- `erp_stock_move`：**流水账**。每笔出入库一行，不可修改，记录批次/方向/来源单据，是审计与追溯的事实；
- `erp_stock_quant`：**即时账**。`产品 × 公司 × 仓库 × 库位(×批次)` 维度的当前结存，单据审核时在事务内更新，带乐观锁 `version`；
- 对账服务：`quant` 结存 = `move` 汇总，提供核对任务，差异常态化报警；
- **库存过账统一收口在 stk 模块的 `StockPostingService`**，采购入库、销售出库、生产领料等都翻译成 `MoveCommand` 提交，不允许业务模块直接写库存表。

### 4.3 业务财务一体化（借鉴 Metasfresh）

- 定义**凭证模板引擎**：`单据类型 × 事件(审核/收付款/完成)` → 凭证分录规则（借/贷科目表达式，从单据字段取值）；
- 单据审核后发布 `FinVoucherRequiredEvent`，fin 模块的 `VoucherPostingService` 按模板生成 `erp_finance_voucher`；
- 模板存数据库、页面可配置——不用改代码就能调整科目映射；
- 一期先跑应收应付台账，二期启用总账过账（见计划书路线图）。

### 4.4 元数据驱动与低代码（借鉴 Odoo）

- 每个业务单据在后端登记一份 **JSON Schema 元数据**（字段、类型、校验、列表列、搜索项、字典来源）；
- 前端 `DynamicTable` / `DynamicForm` 组件按元数据渲染，与 form-create 设计器互通；
- 简单业务表单（如费用登记）可完全低代码；复杂单据（订单/库存）仍走手写页面，但保留元数据供报表与导入导出复用。

### 4.5 多公司数据隔离

- 业务表统一带 `company_id`；MyBatis Plus 拦截器按当前登录用户可见公司范围自动注入过滤；
- 跨公司交易（A 公司销售给 B 公司）在一期不支持，留作四期内部往来主题。

### 4.6 单号规则引擎

- Redis `INCR` + 本地缓存的号段模式，格式：`{前缀}{yyyyMM}{4位序列}`，如 `SO202611000123`；
- 规则存 `bas_serial_rule` 表，按单据类型配置前缀/重置周期/步长，支持手工改号校验。

### 4.7 Chatter 通用记录组件（借鉴 Odoo）

- 任意单据挂载：`biz_chatter` 表，`biz_type + biz_id` 多态关联；
- 三类内容：评论（@人、回复）、关注人（订阅审核与变更通知）、字段变更轨迹（审核时 diff 快照）；
- 前端一个 `<BizChatter :type="sale_order" :id="order.id"/>` 组件全模块复用。

## 5. 前端架构（基于 yudao-ui-admin-vue3 二开）

```
tiangong-ui/
├── src/
│   ├── api/               # 按模块组织的 API 封装（从 OpenAPI 生成基类，手写业务方法）
│   ├── components/        # 通用组件
│   │   ├── BizTable/      # 业务列表：内置分页/筛选/导出/列设置
│   │   ├── BizForm/       # 业务表单：内置主子表、金额计算、校验
│   │   ├── BizChatter/    # 记录动态
│   │   ├── AmountInput/   # 金额输入（精度、大写）
│   │   └── PartnerSelect/ # 往来单位选择器等业务选择器
│   ├── views/
│   │   ├── bas/ pur/ sal/ stk/ fin/ mrp/ crm/ hr/ rpt/   # 业务页面
│   │   └── system/ infra/ bpm/                            # 平台页面（yudao 原有）
│   ├── store/ router/ utils/ hooks/
│   └── lowcode/           # DynamicTable/DynamicForm/form-create 封装
└── vite.config.ts
```

- 权限：菜单级由动态路由控制；按钮级用 `v-hasPermi` 指令（`sal:order:audit` 风格权限串）；
- 单据页面标准范式：`列表页（BizTable）+ 编辑抽屉（BizForm 主子表）+ 详情页（含 Chatter 与审批时间线）`，三期低代码平台接管简单单据；
- 状态管理只放跨页状态，单据草稿用 `useDraft` hook 走 sessionStorage。

## 6. 关键流程时序（示例：销售出库）

```
销售专员      sal 模块        stk 模块           fin 模块        bpm 模块
  │ 创建出库单    │               │                 │              │
  │─────────────►│ (draft)       │                 │              │
  │ 提交审批      │──────────────────────────────────────────────►│
  │              │               │                 │   Flowable 流程
  │              │◄──────────────────────────────────────────────│ 审批通过
  │ 执行审核      │ audit()       │                 │              │
  │              │──MoveCommand──►│ StockPostingService
  │              │               │ 扣减 quant(锁)   │              │
  │              │               │ 写入 move 流水   │              │
  │              │──FinVoucherRequiredEvent────────►│ 生成应收分录  │
  │              │◄─done─────────│                 │              │
  │              │ 发布事件到 Chatter（轨迹+关注人通知）             │
```

## 7. 非功能设计

| 主题 | 方案 |
|------|------|
| 并发控制 | 库存行乐观锁 + 单据审核加分布式锁（单据维度）；虚拟线程提升 IO 密集吞吐 |
| 数据量预估 | 企业自用：年单据 50 万行级，MySQL 单库足够；流水表按年分区预留 |
| 备份 | MySQL 每日全备 + binlog 增量，MinIO 版本化 |
| 可观测 | Spring Boot Actuator + 慢 SQL 监控；操作日志、API 日志沿用 yudao |
| 安全 | 密码 BCrypt、接口幂等（审核/过账接口带 `idempotency_key`）、敏感字段脱敏 |
| 环境约定 | dev / test / prod 三套，`application-{env}.yaml` |
