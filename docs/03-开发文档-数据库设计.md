# 开发文档 · 数据库设计

> 数据库：MySQL 8.0+，字符集 `utf8mb4`，引擎 InnoDB
> 配套：[02-总体架构](./02-开发文档-总体架构.md)

## 1. 设计规范

### 1.1 通用约定

- 命名：`模块前缀_业务名`，模块前缀统一为 `erp_`（如 `erp_sale_order`），平台表沿用 yudao 的 `system_`/`infra_`/`bpm_` 前缀；CRM/HR 用 `crm_`/`hr_`；
- 所有表必须含审计字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| id | bigint | 主键，雪花 ID |
| company_id | bigint | 所属公司（数据隔离，平台表除外） |
| creator / updater | varchar(64) | 创建/更新人（存 userId） |
| create_time / update_time | datetime | 创建/更新时间 |
| deleted | bit(1) | 逻辑删除（MyBatis Plus 插件） |
| tenant_id | bigint | 租户（企业自用恒为 1，保留字段） |

- 金额一律 `decimal(20,6)`（可变单位换算需要 6 位小数），比率 `decimal(10,6)`；
- 业务单据表分**主表 + 明细表**（`_item` 后缀），主表放状态/审批/汇总金额；
- 单据表必须有：`no`（单号，唯一索引）、`status`（统一状态机枚举）、`audit_user_id/audit_time`（审核人/时间）；
- 禁止外键约束（逻辑关联靠索引 + 应用层），禁止跨模块写表。

| 域 | 主表 |
|----|------|

## 2. 基础主数据（bas）

### 2.1 erp_product 产品（借鉴 Odoo product.template）

```sql
CREATE TABLE erp_product (
  id              BIGINT PRIMARY KEY,
  no              VARCHAR(32)  NOT NULL COMMENT '产品编码，唯一',
  name            VARCHAR(128) NOT NULL COMMENT '名称',
  category_id     BIGINT       NOT NULL COMMENT '分类 erp_product_category',
  unit_id         BIGINT       NOT NULL COMMENT '默认计量单位',
  purchase_unit_id BIGINT      COMMENT '采购单位（可空=同默认）',
  sale_unit_id    BIGINT       COMMENT '销售单位',
  spec            VARCHAR(255) COMMENT '规格型号',
  barcode         VARCHAR(64)  COMMENT '条码/SKU',
  purchase_price  DECIMAL(20,6) COMMENT '参考采购价',
  sale_price      DECIMAL(20,6) COMMENT '参考销售价',
  tax_rate        DECIMAL(10,6) COMMENT '默认税率',
  stock_min       DECIMAL(20,6) COMMENT '安全库存下限',
  stock_max       DECIMAL(20,6) COMMENT '库存上限（预警）',
  is_batch        BIT          DEFAULT 0 COMMENT '是否启用批次管理',
  is_serial       BIT          DEFAULT 0 COMMENT '是否启用序列号管理',
  status          TINYINT      COMMENT '0启用 1停用',
  -- 通用审计字段略
  KEY idx_category (category_id), UNIQUE KEY uk_no (no, company_id)
);
```

## 3. 销售域（sal，采购域结构对称，略）

### 3.1 erp_sale_order 销售订单

```sql
CREATE TABLE erp_sale_order (
  id            BIGINT PRIMARY KEY,
  no            VARCHAR(32) NOT NULL COMMENT '单号 SOyyyyMMxxxx',
  partner_id    BIGINT NOT NULL COMMENT '客户',
  order_date    DATE NOT NULL,
  expect_date   DATE COMMENT '期望交期',
  currency_id   BIGINT, exchange_rate DECIMAL(10,6) DEFAULT 1,
  total_qty     DECIMAL(20,6), total_amount DECIMAL(20,6),
  total_tax     DECIMAL(20,6), total_amount_tax DECIMAL(20,6) COMMENT '价税合计',
  discount_amount DECIMAL(20,6) COMMENT '整单优惠',
  settle_type   TINYINT, delivery_address VARCHAR(255),
  remark        VARCHAR(500),
  status        TINYINT NOT NULL COMMENT '10草稿 20待审 30已审 40已完成 50作废',
  audit_user_id BIGINT, audit_time DATETIME,
  bpm_instance_id BIGINT COMMENT '工作流实例',
  UNIQUE KEY uk_no (no, company_id), KEY idx_partner_date (partner_id, order_date)
);

CREATE TABLE erp_sale_order_item (
  id         BIGINT PRIMARY KEY,
  order_id   BIGINT NOT NULL,
  product_id BIGINT NOT NULL,
  unit_id    BIGINT NOT NULL,
  qty        DECIMAL(20,6) NOT NULL,
  price      DECIMAL(20,6) NOT NULL COMMENT '含税单价',
  amount     DECIMAL(20,6) NOT NULL,
  tax_rate   DECIMAL(10,6), tax_amount DECIMAL(20,6),
  outbound_qty DECIMAL(20,6) DEFAULT 0 COMMENT '已出库数量（回写）',
  return_qty DECIMAL(20,6)  DEFAULT 0 COMMENT '已退货数量',
  remark     VARCHAR(255),
  KEY idx_order (order_id)
);
```

> 设计要点：明细表上的 `outbound_qty/return_qty` 是**执行进度回写**，由出库/退货单审核时累加，用于行级关闭判断与欠货报表；订单行全部执行完自动置 `done`。

### 3.2 erp_sale_outbound 销售出库单

主表字段：`order_id`（来源订单，可空=直接出库）、warehouse_id、partner_id、日期、汇总金额、status、审核字段——结构同订单主表；明细表额外含 `location_id`（库位）、`batch_no`（批次）、`order_item_id`（对应订单行）。审核成功 → 调用 `StockPostingService` 出账 → 回写订单行 → 触发应收事件。

## 4. 库存域（stk，核心）

### 4.1 erp_stock_move 库存流水账（Odoo stock.move 思想，只增不改）

```sql
CREATE TABLE erp_stock_move (
  id           BIGINT PRIMARY KEY,
  move_no      VARCHAR(32) NOT NULL COMMENT '流水号',
  biz_type     VARCHAR(32) NOT NULL COMMENT 'purchase_in/sale_out/transfer/check/produce_in/material_out/other…',
  biz_id       BIGINT NOT NULL COMMENT '来源业务单据 id',
  biz_no       VARCHAR(32) COMMENT '来源单号',
  direction    TINYINT NOT NULL COMMENT '1入库 -1出库',
  company_id   BIGINT NOT NULL,
  warehouse_id BIGINT NOT NULL,
  location_id  BIGINT NOT NULL,
  product_id   BIGINT NOT NULL,
  unit_id      BIGINT NOT NULL,
  qty          DECIMAL(20,6) NOT NULL COMMENT '换算为基本单位后的数量(带方向)',
  price        DECIMAL(20,6) COMMENT '成本单价（入库采加权）',
  amount       DECIMAL(20,6) COMMENT '成本金额',
  batch_no     VARCHAR(64), serial_nos JSON COMMENT '序列号列表',
  partner_id   BIGINT COMMENT '交易对手',
  move_time    DATETIME NOT NULL,
  post_user_id BIGINT COMMENT '过账人',
  KEY idx_product_time (product_id, move_time),
  KEY idx_biz (biz_type, biz_id), KEY idx_wh_time (warehouse_id, move_time)
);
```

### 4.2 erp_stock_quant 即时库存账（Odoo stock.quant 思想）

```sql
CREATE TABLE erp_stock_quant (
  id           BIGINT PRIMARY KEY,
  company_id   BIGINT NOT NULL,
  warehouse_id BIGINT NOT NULL,
  location_id  BIGINT NOT NULL,
  product_id   BIGINT NOT NULL,
  batch_no     VARCHAR(64) DEFAULT '' COMMENT '无批次为空串，保证维度完整',
  qty          DECIMAL(20,6) NOT NULL DEFAULT 0 COMMENT '当前结存(基本单位)',
  locked_qty   DECIMAL(20,6) DEFAULT 0 COMMENT '占用量（已审核未出库）',
  avg_cost     DECIMAL(20,6) DEFAULT 0 COMMENT '移动加权平均成本',
  version      INT NOT NULL DEFAULT 0 COMMENT '乐观锁',
  UNIQUE KEY uk_dim (company_id, warehouse_id, location_id, product_id, batch_no)
);
```

> 更新范式：`UPDATE erp_stock_quant SET qty = qty + :delta, avg_cost = CASE WHEN :delta > 0 THEN (:qty+:delta*:price)/(:qty+:delta) ELSE avg_cost END, version = version + 1 WHERE ... AND version = :version`；失败重试 3 次后抛业务异常。**唯一维度键 + 行级原子更新**是账实一致与防超卖的根基。

### 4.3 批次与序列号（Metasfresh 思想）

- `erp_stock_batch`：批次主数据（batch_no, product_id, produce_date, expire_date, supplier_id）；启用批次的产品，`move/quant` 必须带 batch_no；
- 序列号不入 quant 维度（维度爆炸），存 `move.serial_nos` JSON + 独立 `erp_stock_serial` 台账（serial_no, product_id, status 在库/出库, current_location），一对一追溯。

### 4.4 其他库存单据

| 表 | 说明 |
|----|------|
| erp_stock_transfer(_item) | 调拨单：调出仓库→调入仓库，审核生成方向相反的两条 move |
| erp_stock_check(_item) | 盘点单：`账面数量`(锁定时点 quant 快照)、`实盘数量`、`盈亏数量`；审核生成盘盈入/盘亏出 move |
| erp_stock_in / erp_stock_out | 其他出入库（赠品/报废/领用等） |

## 5. 财务域（fin）

### 5.1 应收应付台账

```sql
CREATE TABLE erp_finance_receivable (   -- payable 结构对称
  id            BIGINT PRIMARY KEY,
  no            VARCHAR(32) COMMENT '应收单号',
  biz_type      VARCHAR(32) COMMENT 'sale_out/sale_return/other',
  biz_id BIGINT, biz_no VARCHAR(32) COMMENT '来源单据（出库单）',
  partner_id    BIGINT NOT NULL,
  currency_id BIGINT, exchange_rate DECIMAL(10,6) DEFAULT 1,
  amount        DECIMAL(20,6) NOT NULL COMMENT '应收金额',
  received_amount DECIMAL(20,6) DEFAULT 0 COMMENT '已核销金额',
  due_date      DATE COMMENT '账期到期日',
  status        TINYINT COMMENT '未结清/部分/已结清/作废',
  settle_date   DATE COMMENT '核销完成日',
  KEY idx_partner_status (partner_id, status)
);
```

### 5.2 收付款单（主子表：付款头 + 核销明细行）

```sql
CREATE TABLE erp_finance_receipt (
  id BIGINT PRIMARY KEY, no VARCHAR(32) COMMENT 'ARyyyyMMxxxx',
  partner_id BIGINT NOT NULL, account_id BIGINT NOT NULL COMMENT '收款账户',
  receipt_date DATE NOT NULL, amount DECIMAL(20,6) NOT NULL,
  unreceipted_amount DECIMAL(20,6) COMMENT '剩余未分配',
  status TINYINT, audit_user_id BIGINT, audit_time DATETIME,
  remark VARCHAR(500), UNIQUE KEY uk_no(no, company_id)
);
CREATE TABLE erp_finance_receipt_item (
  id BIGINT PRIMARY KEY,
  receipt_id BIGINT NOT NULL,
  receivable_id BIGINT NOT NULL COMMENT '核销的应收单',
  amount DECIMAL(20,6) NOT NULL COMMENT '本次核销金额',
  KEY idx_receipt (receipt_id)
);
```

> 核销规则：审核时在事务内校验 `Σ明细 ≤ min(收款金额, 各应收未核销额)`，回写 `receivable.received_amount` 与状态；一个收款单可拆多张应收（一付多核），一张应收可被多张收款单核销。

### 5.3 总账凭证（二期启用，Metasfresh 联动思想）

```sql
CREATE TABLE erp_finance_voucher (
  id BIGINT PRIMARY KEY, no VARCHAR(32) COMMENT '凭证字 PZ202611-0001',
  voucher_date DATE NOT NULL, period VARCHAR(6) COMMENT '会计期间 2026-11',
  biz_type VARCHAR(32) COMMENT '来源业务(可空=手工)',
  biz_id BIGINT, source_no VARCHAR(32),
  total_debit DECIMAL(20,6), total_credit DECIMAL(20,6),
  status TINYINT COMMENT '草稿/已过账/已作废', posted_time DATETIME,
  UNIQUE KEY uk_no(no, company_id)
);
CREATE TABLE erp_finance_voucher_item (
  id BIGINT PRIMARY KEY, voucher_id BIGINT,
  subject_id BIGINT NOT NULL, summary VARCHAR(255),
  debit DECIMAL(20,6) DEFAULT 0, credit DECIMAL(20,6) DEFAULT 0,
  partner_id BIGINT, KEY idx_voucher(voucher_id)
);
CREATE TABLE erp_voucher_template (    -- 凭证模板：业务→分录规则，页面可配
  id BIGINT PRIMARY KEY,
  biz_type VARCHAR(32), event VARCHAR(32) COMMENT '如 sale_out@audit',
  lines JSON COMMENT '[{summary:"{partner.name}销售",subject:"6001",direction:"credit",amount:"{item.amount_tax}"}]',
  enabled BIT
);
```

> 约束：`total_debit = total_credit` 且每行借贷不同负；模板表达式取值失败则凭证挂起待人工，**业务单据不因此回滚**（解耦财务与业务异常）。

## 9. 索引与性能约定

1. 所有主子表：子表必须有 `idx_主表外键`；单据表必须有 `uk_no(no, company_id)`；
2. 报表统计尽量走汇总表/定时任务物化（如日库存结存表），避免大表实时聚合；
3. `erp_stock_move` 按年分区的 DDL 在数据量过千万时启用（预留 `PARTITION BY RANGE` 迁移脚本）；
4. 字典、配置类表走 Redis 缓存（Cache-Aside，更新时删缓存）。
