# 天工 ERP 项目计划书

> **项目代号**：天工 ERP（TianGong ERP，取"巧夺天工、集成众长"之意，可替换）
> **定位**：企业自用的全模块 ERP 系统
> **技术基线**：Spring Boot 3 + Vue 3 · 模块化单体架构
> **文档版本**：v1.0 · 2026-11-07 · 起草：ZCode

---

## 1. 项目背景与目标

### 1.1 背景

现有开源 ERP 各有短板：

- **Odoo** 功能生态最强，但技术栈是 Python/PostgreSQL，与团队 Java + Vue 的能力不匹配，二次开发成本高；
- **ruoyi-vue-pro（芋道）** 的 Spring Boot + Vue3 工程化极优秀，但其 ERP 模块偏"轻量进销存"，缺少生产制造、多公司、业务财务联动等深度能力；
- **Metasfresh** 有最完整的制造业 MRP 能力，但是 Java 老一代架构（ADempiere 血统），UI 陈旧、本地化差。

本项目以 **yudao 工程骨架为底座**、**Odoo 的模块化与元数据思想为设计哲学**、**Metasfresh 的制造与财务深度为业务蓝本**，构建一套贴合本企业业务的 ERP。

### 1.2 项目目标

| 目标 | 衡量标准 |
|------|---------|
| 业务闭环 | 询价→报价→订单→出入库→开票→收付款→凭证，全链路单据贯通 |
| 账实一致 | 库存双录（流水账+即时账），月末盘点差异可解释 |
| 业务财务一体化 | 业务单据审核自动生成应收应付与总账凭证（Metasfresh 模式） |
| 模块可插拔 | 任何业务模块可独立停用/启用（Odoo 模式），不影响其他模块 |
| 低代码可扩展 | 新增简单业务表单无需写前端（元数据驱动，Odoo 思想） |
| 上线周期 | 一期（进销存+财务核心）在 3 个月内具备试运行条件 |

### 1.3 非目标（本期明确不做）

- 不做 SaaS 多租户对外运营（保留租户开关但默认关闭，企业自用单租户）；
- 不做 Odoo 级别的应用市场/插件商店生态；
- 不做移动端原生 App（三期提供 H5 适配即可）。

## 2. 参考项目分析与"取什么、弃什么"

### 2.1 四大项目对比

| 维度 | Odoo | ruoyi-vue-pro | yudao-ui-admin-vue3 | Metasfresh |
|------|------|---------------|---------------------|------------|
| Stars（2026-11） | 55.6k | 40.3k | 4.0k（前端） | 2.5k |
| 技术栈 | Python + PostgreSQL + OWL | Spring Boot 3 + MyBatis Plus | Vue3 + TS + Element Plus | Java（ADempiere 系）+ PostgreSQL |
| 业务深度 | 全领域、生态第一 | 进销存/CRM/支付/商城，深度中等 | — | 制造业 MRP、财务联动最强 |
| 工程化 | 中（自有框架） | **极高**（代码生成、规范完善） | **极高** | 低（老架构） |
| 中国本地化 | 差（发票/电子税局等） | **极好** | **极好** | 差 |
| 学习/二开成本 | 高（Python + OWL） | 低 | 低 | 很高 |

### 2.2 借鉴映射表（本项目的设计来源）

| 借鉴点 | 来源 | 在本项目的落地方式 |
|--------|------|-------------------|
| 模块化单体骨架、RBAC、数据权限、代码生成、操作日志 | ruoyi-vue-pro | 直接采用其 Maven 分包结构与 `system`/`infra` 基础模块，作为底座 |
| 前端工程、动态路由、标签页、富文本、导入导出组件 | yudao-ui-admin-vue3 | 作为前端基座，二次封装 ERP 业务组件 |
| **插件式模块机制**（app 可装可卸）、模块间只通过接口依赖 | Odoo | Maven 模块 + SPI 扩展点 + `ModuleRegistrar` 启动注册器 |
| **元数据驱动的表单/列表**（一个 model 定义生成整套 CRUD 界面） | Odoo | 后端 model 元数据 + 前端 `DynamicTable/DynamicForm` 渲染器 + form-create |
| **Chatter 记录动态**（单据上的评论/关注/变更轨迹） | Odoo | 通用 `biz_chatter` 组件，`biz_type + biz_id` 关联任意单据 |
| **多公司 + 多币种** | Odoo / Metasfresh | `company_id` 数据隔离 + 币种/汇率主数据 |
| **库存双录**（stock.move 流水 + stock.quant 即时账） | Odoo | `erp_stock_move` 与 `erp_stock_quant` 分表，月末可对账 |
| **BOM 多层级 + MRP 运算 + 生产工单 + 领退料 + 报工** | Metasfresh | `erp_mrp_*` 系列表与运算服务 |
| **业务单据自动生成会计凭证**（ Accounting Schema 联动） | Metasfresh / Odoo | 单据审核钩子 → `erp_finance_voucher` 自动过账 |
| **批次/序列号全程追溯** | Metasfresh | 批次主数据 + 库存移动批次明细，正反向追溯 |

### 2.3 明确不采纳的部分

- Odoo 的 XML 视图引擎：改为 JSON Schema 元数据 + Vue 渲染（更贴合前端生态）；
- Metasfresh 的 Swing/老 WebUI、ADempiere 字典表风格（`C_BPartner` 这类前缀命名）：采用现代 REST + 语义化命名；
- yudao 的商城/会员/AI 等模块：不在本企业需求内，裁剪不引入。

## 3. 功能规划（全模块全家桶）

### 3.1 模块全景图

```
┌─────────────────────────── 前端 Vue3 + Element Plus ───────────────────────────┐
│  工作台/门户 │ 业务单据中心 │ 报表中心 │ 移动端 H5 │ 低代码表单设计器              │
└──────────────────────────────────┬───────────────────────────────────────────┘
                                   │ REST API
┌──────────────────────────────────┴───────────────────────────────────────────┐
│                          平台层（来自 yudao 底座）                             │
│  system(用户/角色/菜单/租户/多公司) │ infra(代码生成/文件/定时任务/API日志)     │
│  bpm(Flowable 工作流) │ 报表引擎 │ 消息通知 │ 导入导出 │ 打印模板                │
├──────────────────────────────────────────────────────────────────────────────┤
│                          ERP 业务层（本项目自研）                              │
│  基础主数据 │ 采购管理 │ 销售管理 │ 库存管理 │ 财务管理 │ 生产制造             │
│  CRM 客户关系 │ HR 人事 │ 设备/资产(可选) │ 质量管理(可选)                     │
├──────────────────────────────────────────────────────────────────────────────┤
│                          支撑设施                                             │
│  MySQL 8 │ Redis 7 │ MinIO │ Quartz │ Flowable │ 单号规则引擎 │ Chatter 服务  │
└──────────────────────────────────────────────────────────────────────────────┘
```

### 3.2 各模块功能清单

**① 基础主数据（bas）**：产品与分类、多计量单位、往来单位（客户/供应商合一，借鉴 Odoo `res.partner`）、多公司、多币种汇率、仓库与库位、会计科目、结算账户、单号规则。

**② 采购管理（pur）**：询价单 → 采购报价 → 采购订单 → 采购入库 → 采购退货 → 供应商对账 → 采购付款申请。含审批流、到货提醒、价格策略（最近价/合同价）。

**③ 销售管理（sal）**：销售报价 → 销售订单 → 发货通知 → 销售出库 → 销售退货 → 客户对账 → 收款核销。含信用额度控制、订单毛利预估。

**④ 库存管理（stk）**：入库/出库/调拨/盘点/其他出入库、即时库存与库存流水双账、批次与序列号、库存预警（上限/下限）、安全库存、先进先出生效期管理、库存月结。

**⑤ 财务管理（fin）**：应收应付台账、发票登记、收付款与核销、费用报销、总账凭证（业务单据自动过账 + 手工凭证）、科目余额表、三大报表（资产负债/利润/现金流量简版）、月结年结。

**⑥ 生产制造（mrp，Metasfresh 蓝本）**：BOM 多版本多层级、工艺路线与工序、MRP 运算（净需求/毛需求）、生产工单、车间领退料、生产报工、完工入库、委外加工。

**⑦ CRM 客户关系（crm）**：线索池 → 商机跟进（销售漏斗）→ 客户公海 → 跟进记录 → 合同管理 → 数据看板。（与销售模块打通：商机转销售订单）

**⑧ HR 人事（hr）**：组织架构、员工档案、考勤打卡（对接钉钉/企微可选）、请假审批（走 BPM）、薪资核算（简版）。

**⑨ 工作流（bpm）**：Flowable 引擎，采购/销售/费用/请假等单据挂接审批流，支持会签/或签/加签/转办、钉钉/企微消息提醒。

**⑩ 报表与门户（rpt）**：通用报表引擎（JmReport 或积木报表）、经营驾驶舱大屏（ECharts）、自助查询。

### 3.3 分期路线图

| 阶段 | 周期 | 交付内容 | 里程碑 |
|------|------|---------|--------|
| **一期 MVP** | 第 1~3 月 | 平台底座搭建 + 基础主数据 + 采购 + 销售 + 库存双账 + 财务核心（应收应付/收付款/发票）+ BPM 基础审批 | 进销存财务闭环试运行 |
| **二期** | 第 4~6 月 | 生产制造全套（BOM/MRP/工单/报工）+ 业务自动过账（总账凭证）+ 批次序列号 + 盘点月结 | 业务财务一体化上线 |
| **三期** | 第 7~9 月 | CRM + HR + 报表大屏 + 低代码表单平台 + 移动端 H5 + 钉钉/企微集成 | 全家桶完整交付 |
| **持续迭代** | 10 月起 | 质量管理、设备资产、需求池消化 | — |

## 5. 里程碑计划（按 2 后端 + 1 前端 + 1 全栈负责人估）

> 若人力不同，按人月等比缩放；关键路径为「库存双账 → 业务过账」。

| 里程碑 | 时间 | 关键交付物 |
|--------|------|-----------|
| M0 架构就绪 | 第 2 周末 | 代码骨架、CI/CD、数据库规范、四大底座模块跑通 |
| M1 主数据+单据框架 | 第 6 周末 | 往来单位/产品/仓库 + 单号引擎 + 通用单据组件（Chatter/审批/打印） |
| M2 进销存闭环 | 第 10 周末 | 采购订单→入库、销售订单→出库、库存双账可对 |
| M3 财务核心 | 第 13 周末 | 应收应付、收付款核销、发票登记，**一期试运行** |
| M4 制造+过账 | 第 20 周末 | BOM/工单/领料/报工 + 业务自动凭证 |
| M5 全模块 | 第 26 周末 | CRM/HR/报表大屏/低代码表单，**二期验收** |

## 6. 风险与对策

| 风险 | 等级 | 对策 |
|------|------|------|
| "全家桶"范围蔓延导致烂尾 | 高 | 严格按一期→三期顺序，每期设"可上线的最小闭环"，砍需求不砍质量 |
| 业务财务自动过账复杂度高 | 高 | 二期才做过账；一期先以应收应付台账过渡；凭证规则做成可配置映射表 |
| 多公司数据隔离引入的 Bug | 中 | MyBatis Plus 拦截器统一注入 `company_id`，禁止手写 SQL 绕过 |
| yudao 底座升级冲突 | 中 | 底座代码 vendor 进仓库独立维护，不追上游小版本，只同步安全补丁 |
| MRP 运算性能 | 中 | BOM 限制层级 ≤10，运算走异步任务 + 进度条，结果落库 |
| 库存并发（超卖/负库存） | 中 | `stock_quant` 行级锁 + 乐观版本号；单据审核才过账 |

## 7. 成功标准

1. 一期上线后 3 个月内，采购/销售/库存业务 100% 走系统，纸质单据归零；
2. 库存账实相符率 ≥ 99%（月盘）；
3. 二期后财务凭证 80% 以上由业务单据自动生成；
4. 新增一张简单业务单据（表单+列表+导出+审批）的交付时间 ≤ 1 天（低代码 + 代码生成器）。
